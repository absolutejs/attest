## 0.2.1 — 2026-10-17

### Fixed

- **Re-attesting an unchanged artifact no longer fails on the transparency log's duplicate-entry 409** (`toleratingExistingLogEntries`)
  Signing the same payload for the same digest with the same key yields the same transparency-log entry, and Rekor refuses a second copy with HTTP 409 ("an equivalent entry already exists"). Re-attesting an unchanged, reused image therefore failed although its attestation was already published. `publish-image` and `sign-blobs` now treat a sign or attest refused only that way as done; the verification that follows each one in the plan still has to find the attestation for that digest and identity. Every other failure, and any verification failure, still fails. `toleratingExistingLogEntries` wraps a command runner this way.
